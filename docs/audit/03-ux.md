# 03 — UI/UX walkthrough

*Phase 3. Two task-based runs through the product as it stands after Phases
1–2, screenshots at desktop and phone width, light and dark, scored against
the heuristics that matter for a tool someone uses weekly: can I tell what
state things are in, can I recover from a mistake, does the same thing look
the same everywhere, do I have to remember anything.*

Setup: the worktree's web app (Next dev server) in the in-app browser; the
API is the primary checkout's on :4000 (the UI proxies `/api`), so the
compose it triggers runs the OLD pipeline — the walkthrough judges the
screens, not the output. Compose is exercised through the lab bench instead.

## Persona B — the agent, through the API

Task: the `instagram` skill's sequence (`GET /businesses` → `POST /projects`
→ `POST /projects/:id/compose` → `GET` → `PATCH` → `POST …/export`), run at
$0 against the primary API on :4000 (compose skipped — it runs the old code
there; the lab bench covers it).

- `GET /businesses` returns the leaked scaffold `__render-check-9a7ae6e1`
  with `hasRecipe: true`, `photoCount: 0` and no profile — the root of the
  Desk's phantom brand. The list should exclude scaffold names.
- `POST /projects` with caption, hashtags, `dmKeyword` and `audience` lands
  them all as editable drafts, as the skill expects. `GET` returns the joined
  `brandKit`, `media` and `promptUpdates`.
- `PATCH /projects/:id` with a photo missing its `id` still answers
  `{"fieldErrors":{"slides":["Required"]}}` — no slide index, no field path.
  FEEDBACK.md logged this on 2026-08-21; it is still open. Surface zod's issue
  paths (`slides.0.photos.0.id`) or default the id server-side.
- `DELETE` is clean.

## Instagram-native checks

- **Feed legibility at 393px.** The Studio's phone view stacks the deck at
  reading width; on the post-backlog decks every headline, row and body reads
  at that size, and the zoomed screenshots read where the whole-UI cards did
  not. The remaining fails are photographs that are the wrong subject, not
  type.
- **Story safe areas.** A 9:16 Dynatós deck composed with no model
  ([sheet](sheets/ig--dynatos-story.jpg)): the 250px top and bottom reserves
  hold on all six slides, the close's button sits above the bottom band,
  0 overflow. The story stylesheet's larger type (headline 124, stat 260)
  reads at feed scale.
- **The first-slide hook test.** Covers after Phase 1 pass it: "A quiet
  January should not undo December.", "Spotless car. Smell back in a week.",
  "One bad week from quitting?". The one exception in the clean set was
  Sonnet 5's, which promoted a tagline to the cover.
- **Caption and hashtags.** The lab decks carry no caption (the route
  generates it on demand); the Studio's caption tile says so plainly ("No
  caption yet — the post ships silent without one") and the keyword lives in
  `settings.dmKeyword`, so the close and the caption cannot drift apart.
- **Stories.** The database holds two promo stories, one seeded story and no
  composed stories: the product's story path is exercised only by
  `promo-story`. The 9:16 recipe overrides work; nobody has asked them to.
